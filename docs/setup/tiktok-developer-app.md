[API](https://developers.tiktok.com/docs/en/content-posting-api-reference-upload-video): inbox init allows 6 calls/min/token and 5 pending shares/24h. [Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post) requires fresh [creator-info](https://developers.tiktok.com/docs/en/content-posting-api-reference-query-creator-info) before init: check privacy, interactions and maximum duration. Adapter enforces private-account options/duration and disables interactions. Production requires an editable export UI and explicit per-post consent; this CLI is a test integration.

[Transfer](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide): FILE_UPLOAD uses sequential PUTs with Content-Length/Range, 5–64 MB chunks, floor(size/chunk_size) chunks (1–1000), trailing bytes joined to final chunk (up to 128 MB). Below 5 MB upload whole; above 64 MB use multiple chunks. Adapter uses 10 MB chunks, maximum 4 GB. PULL_FROM_URL needs verified owned domain/prefix, HTTPS, no redirects, accessibility throughout download (one-hour timeout); local clips use FILE_UPLOAD.

[Tokens](https://developers.tiktok.com/docs/en/oauth-user-access-token-management): current lifetimes are 2h access/180d refresh; returned expiry fields are authoritative. Refresh rotates tokens; adapter refreshes on missing access/invalid-token 401, persisting both through secrets. [Errors/status](https://developers.tiktok.com/docs/en/content-posting-api-reference-get-video-status): scope errors need consent; 429 retries later; spam/private-only/invalid privacy block posting. HTTP 200 can contain errors. Ambiguous init needs manual inspection; persisted publish IDs prevent duplicate initialization. Inbox/private completion is not public publication. Analytics need separate Display API permission.
